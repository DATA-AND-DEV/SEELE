# F1 — O protocolo da 1.0: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deixar o `seele-proto` pronto para falar o Servidor 1.0, que é o protocolo 9: a faixa no `Hello`, a recusa que toda versão lê, a mensagem desconhecida que não mata a sessão, a voz com número próprio, os bytes-ouro que congelam a linha 1 e a prova de identidade amarrada ao servidor (S2).

**Architecture:** Tudo o que define bytes mora no `seele-proto` e é função pura: sem E/S, sem `quinn` e compilável para `wasm32`. O `seele-core` e o `seele-server` mudam só o mínimo para compilar, mais o S2. O comportamento novo de sessão (pular a desconhecida, recusar com o carimbo do par, carimbar com a versão negociada) fica pronto no `seele-proto`. Ele só é ligado em `session.rs` e `client.rs` na fase da sessão do Plano 3, depois do lote G-servidor e do lote I.

**Tech Stack:** Rust 2021, `postcard` 1.1.3 (lê por posição), `serde`, `sha2`, `ed25519-dalek` 3, `quinn` 0.11 e `rustls` 0.23 nos testes de conformidade.

**Spec:** `docs/superpowers/specs/2026-10-08-0.16-design.md` (§1, §2 «F1», §3). Documentos de apoio: o levantamento `docs/superpowers/sdd/2026-10-08-0.16/levantamentos/F1-contrato-de-fio.md`, a análise `docs/analise-para-a-1.0-2026-09-22.md` §3.1 e §3.2, e a spec de 23/09, `docs/superpowers/specs/2026-09-23-sala-pessoal-por-codigo-design.md`, `:213-233`. - [ ] **Passo 1: escrever o adendo, com estas seções e estas regras**

1. **O número e a linha.**
   - `PROTOCOL_VERSION` é o maior número que a build fala, e `VERSAO_MINIMA` é o menor.
   - A tabela congelada é `1..=8` → antes da 1.0 e `9..` → linha 1. Um número acima do máximo da build é «posterior», e ela não sabe nomeá-lo.
   - Toda 1.x tem `VERSAO_MINIMA = 9`, e é isso que torna «1.x nunca quebra o fio» verdade.
   - O Servidor 1.0 fala `[9, 9]`.
2. **O `Hello`.**
   - Ele leva `faixa: Faixa { minima, maxima }` no lugar de `version`.
   - O quadro do `Hello` sai carimbado com a **mínima** de quem liga, para que qualquer servidor da mesma linha o leia.
3. **Quem desce.**
   - O servidor decide `n = min(maxima_do_par, PROTOCOL_VERSION)`, desde que `n ≥ max(minima_do_par, VERSAO_MINIMA)`. Senão, recusa.
   - O cliente adota como `n` o carimbo do primeiro quadro do servidor, desde que esteja na faixa dele.
4. **O carimbo.**
   - Depois do `Hello`, os dois lados carimbam todo quadro com `n` (`encode_em`).
   - `decode` aceita qualquer carimbo da própria faixa.
   - Na 1.0 a faixa é `[9, 9]`, então `encode_em(n, …) == encode(…)`.
5. **A recusa legível.**
   - O quadro é `[c, 11, 0]`, isto é, `Disconnecting { Incompatible }`.
   - Para um par que carimbou `b < 9`, `c = b`, porque só assim uma 0.11–0.15 o lê.
   - Para um par que carimbou `b ≥ 9`, `c = PROTOCOL_VERSION` de quem recusa. A linha de quem recusa viaja no byte 0.
   - Quem recebe um primeiro quadro com carimbo fora da faixa lê o número de quem respondeu em `ControlError::UnsupportedVersion { found }`, e a linha em `linha_de(found)`.
   - Um servidor 0.15, diante de um `Hello` 9, responde `[8, 11, 9]` (`ProtocolViolation`). O 8 já diz «Servidor 0.15». **Isso é leitura do código de `54f542f`, e não medida.** A medida com o `seeled` 0.15.1 de verdade fica para a F6 (spec-mestre §1).
6. **O que fica congelado:** o byte 0, o ordinal 11 de `ServerMessage`, o `Incompatible = 0` e o ALPN `seele/1`. Um servidor 2.0 continua aceitando o ALPN `seele/1` só para poder recusar com legibilidade.
7. **A mensagem desconhecida.**
   - Na lista de cima (`ClientMessage` e `ServerMessage`), um ordinal ≥ ao número de variantes conhecidas vira `Lido::Desconhecida`. Ele é pulado e contado, e só o primeiro vai para o registro.
   - Nos enums aninhados, nada muda: quem manda cala a variante para quem não a entende (`session::entende_a_mensagem`). Ignorar um `Disconnecting` com razão desconhecida calaria o fim da sessão.
8. **A voz.**
   - `MEDIA_HEADER_VERSION = 1` é o número dos onze bytes. Ele sobe só quando esses bytes mudarem.
   - O servidor repassa intacto, e quem lê confere igualdade estrita. A tela já é assim (`screen.rs:78`).
9. **O S2.**
   - A prova é `Sign(ROTULO_PROVA_DE_CLIENTE ‖ fp ‖ nonce)`, com o rótulo `"SEELE/1 prova-de-cliente\0"`.
   - `fp` são os 32 bytes do SHA-256 do DER do certificado **de longa duração** do servidor, o mesmo do `fp=` do link. No nativo, sai do certificado que o TLS aceitou. No navegador, sai do link.
   - `nonce` tem exatamente 32 bytes, e o cliente recusa outro tamanho.
   - O rótulo do `MORO2` é `"SEELE-ENC/2 moro\0"`. O certificado da sala é assinado sobre um `TBSCertificate`, que começa por `0x30`. O CertificateVerify do TLS 1.3 começa por 64 × `0x20`. Os quatro espaços são disjuntos pelo primeiro byte ou pelo rótulo terminado em NUL, e um teste em `assinatura.rs` prende isso.
10. **O assento do E2EE.**
    - `Hello.material_e2ee` e `PersonProfile.material_e2ee` entram como `Option<Vec<u8>>`, com até 256 bytes, e vão sempre `None` na 1.0.
    - O motivo é a chave de mídia por sala (`specs/08-seguranca.md:59-63`). Cada participante precisa publicar uma vez por sessão um material de acordo de chave assinado pela identidade, e quem o apresenta aos outros é o `PersonProfile`, que viaja em `PersonJoined` e `PersonPresent`.
    - A rotação da chave pode chegar como mensagem nova numa 1.x.
    - **Esta escolha de lugar é técnica e está aberta à orquestradora até o 9 congelar.**
11. **O que fica para o vocabulário:**
    - as APIs de MOD no `Hello` e `ModAnunciado.api` (D-fio-7), que mudam o `Hello` de novo antes do congelamento;
    - `Tocando` e as razões a partir do 18;
    - os membros do FORA DO AR;
    - os hashes do celular.
12. **0.15 e 0.16:**
    - não conversam;
    - um cliente 0.15 lê «VERSÃO INCOMPATÍVEL» quando o lado servidor do Plano 3 for ligado (`[8, 11, 0]`);
    - um cliente 0.16 lê «Servidor 0.15» pelo byte 0 quando o lado cliente for ligado.

```rust
//! O enquadramento de 4 bytes de todo fluxo do SEELE: o comprimento em
//! big-endian, depois o quadro. Sem E/S, para que o nativo e o `wasm` do
//! celular usem a mesma regra (ADR 0057).

use crate::control::{ControlError, MAX_FRAME_LEN};

/// Bytes do prefixo de comprimento.
pub const PREFIXO_LEN: usize = 4;

/// O comprimento que o prefixo anuncia, conferido contra o teto **antes** de
/// qualquer alocação (`specs/08-seguranca.md`).
///
/// # Errors
///
/// [`ControlError::Empty`] para zero, [`ControlError::TooLong`] acima de [`MAX_FRAME_LEN`].
pub fn comprimento(prefixo: [u8; PREFIXO_LEN]) -> Result<usize, ControlError> {
    let len = u32::from_be_bytes(prefixo) as usize;
    if len == 0 {
        return Err(ControlError::Empty);
    }
    if len > MAX_FRAME_LEN {
        return Err(ControlError::TooLong { len });
    }
    Ok(len)
}

/// Prefixo e quadro num `Vec` só, que é o que vai para o fluxo.
///
/// # Errors
///
/// Os mesmos de [`comprimento`], aplicados ao quadro de saída.
pub fn enquadrar(quadro: &[u8]) -> Result<Vec<u8>, ControlError> {
    let len = u32::try_from(quadro.len()).map_err(|_| ControlError::TooLong { len: quadro.len() })?;
    comprimento(len.to_be_bytes())?;
    let mut saida = Vec::with_capacity(PREFIXO_LEN + quadro.len());
    saida.extend_from_slice(&len.to_be_bytes());
    saida.extend_from_slice(quadro);
    Ok(saida)
}

/// Junta bytes que chegam em pedaços e devolve quadros inteiros. É o que um
/// leitor sem `read_exact` precisa, como o do WebTransport.
#[derive(Debug, Default)]
pub struct Desenquadrador {
    pendente: Vec<u8>,
}

impl Desenquadrador {
    /// Acrescenta o que chegou.
    pub fn empurrar(&mut self, bytes: &[u8]) {
        self.pendente.extend_from_slice(bytes);
    }

    /// O próximo quadro inteiro, se já chegou.
    ///
    /// # Errors
    ///
    /// Os de [`comprimento`]. Depois de um erro o fluxo está perdido, e quem
    /// chamou deve fechá-lo.
    pub fn proximo(&mut self) -> Result<Option<Vec<u8>>, ControlError> {
        let Some(prefixo) = self.pendente.get(..PREFIXO_LEN) else {
            return Ok(None);
        };
        let mut lido = [0_u8; PREFIXO_LEN];
        lido.copy_from_slice(prefixo);
        let fim = PREFIXO_LEN + comprimento(lido)?;
        let Some(quadro) = self.pendente.get(PREFIXO_LEN..fim).map(<[u8]>::to_vec) else {
            return Ok(None);
        };
        self.pendente.drain(..fim);
        Ok(Some(quadro))
    }
}
```

pub fn confere_o_carimbo(carimbo: u8) -> Result<u8, Incompatible> {
    if carimbo > PROTOCOL_VERSION {

    }

pub fn encode_em<T: Serialize + Validate>(versao: u8, message: &T) -> Result<Vec<u8>, ControlError> {

pub trait ListaDeCima: for<'de> Deserialize<'de> + Validate {

    /// é de um vocabulário mais novo.

}

/// O que um quadro da lista de cima trouxe.
#[derive(Debug, Clone, PartialEq)]
pub enum Lido<T> {
    /// Uma mensagem que esta build conhece.
    Mensagem(T),
    /// Uma variante de um vocabulário mais novo. Quem lê pula, conta e segue:
    /// o quadro tem comprimento próprio, então pular não desalinha nada.
    Desconhecida {
        /// O ordinal que veio.
        ordinal: u32,
    },
}

/// Como [`decode`], mas uma variante que esta build não conhece vira
/// [`Lido::Desconhecida`] em vez de [`ControlError::Malformed`].
///
/// # Errors
///
/// Os mesmos de [`decode`], para tudo que não é ordinal desconhecido.
pub fn decode_da_lista<T: ListaDeCima>(frame: &[u8]) -> Result<Lido<T>, ControlError> {
    if frame.len() > MAX_FRAME_LEN {
        return Err(ControlError::TooLong { len: frame.len() });
    }
    let Some((version, body)) = frame.split_first() else {
        return Err(ControlError::Empty);
    };
    crate::version::confere_o_carimbo(*version).map_err(|_| ControlError::UnsupportedVersion {
        found: *version,
        expected: PROTOCOL_VERSION,
    })?;
    let ordinal = ler_ordinal(body).ok_or(ControlError::Malformed)?;
    if ordinal >= T::CONHECIDAS {
        return Ok(Lido::Desconhecida { ordinal });
    }
    decode::<T>(frame).map(Lido::Mensagem)
}

/// O ordinal de variante que o `postcard` escreve: um varint sem sinal, sete
/// bits por byte, o menos significativo primeiro.
fn ler_ordinal(corpo: &[u8]) -> Option<u32> {
    let mut valor: u32 = 0;
    for (posicao, byte) in corpo.iter().take(5).enumerate() {
        let deslocamento = u32::try_from(posicao).ok()?.checked_mul(7)?;
        valor |= u32::from(byte & 0x7f).checked_shl(deslocamento)?;
        if byte & 0x80 == 0 {
            return Some(valor);
        }
    }
    None
}
