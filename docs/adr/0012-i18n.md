# 0012 — i18n desde M0, sem milestone próprio

Status: aceito por default
Contexto: `specs/10-convencoes.md` exige i18n desde o início, com pt-BR e en, e proíbe literal de string na interface. **Nenhum dos sete milestones de `specs/09-roadmap.md` menciona i18n** (lacuna G4 do plano). Retrofit de i18n é exatamente o custo que `10` diz querer evitar.
Decisão: i18n não ganha milestone porque não precisa de um. O que precisa existir desde M0 é a **fronteira**, não o catálogo:

- Todo motivo de erro e todo estado que a interface apresenta é `enum` em `seele-proto` ou `seele-core`. Nunca `String`.
- Nenhum crate abaixo das cascas formata texto para humano. `seele-audio` e `seele-core` emitem dado puro.
- A tabela de tradução nasce em M4, junto com a primeira casca. Até lá não há o que traduzir.

Alternativas: escolher agora uma biblioteca (`fluent`, `gettext`) e montar catálogo vazio. Descartado — catálogo sem interface é cerimônia; a escolha da biblioteca é barata em M4 e cara de acertar às cegas agora.
Consequências: mais fácil — a decisão de biblioteca fica para quando houver tela real. Mais difícil — exige disciplina de enum desde a primeira linha; um `format!` de mensagem de erro dentro de `seele-core` já é a dívida.

Observação: o glossário de `specs/07-estetica.md` é normativo nos dois idiomas por `10`, mas só existe em português. Fechado em `docs/glossario.md` (M0.7), que é pré-requisito de qualquer nome de tipo.
